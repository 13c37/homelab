# lain stats implementation plan

> **for agentic workers:** required sub-skill: use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. steps use checkbox (`- [ ]`) syntax for tracking.

**goal:** log every played track and every vc session in lain's database and answer `lain stats` / `lain top` with server and personal numbers.

**architecture:** two new drizzle tables (postgres schema, pglite at runtime) filled by a small recorder hooked into the lavalink player events. a query module turns the rows into overview, personal and top lists. two text commands render them.

**tech stack:** typescript on bun, discord.js, lavalink-client, drizzle-orm + pglite, `bun test`.

**spec:** [docs/superpowers/specs/2026-11-27-lain-stats-design.md](../specs/2026-11-27-lain-stats-design.md)

## global constraints

- all code changes go into the upstream lavamusic checkout at sha `32e5f73727f1d9f038795806188d7d992e608b4f` and ship as `stacks/lain/lavamusic/lain.patch` (regenerate with `git add -A && git diff --cached 32e5f737 > <repo>/stacks/lain/lavamusic/lain.patch`). never edit `/opt/homelab` on the server.
- new lain code lives under `src/lain/stats/` and every touched upstream line gets a `// lain:` comment, like the existing patch.
- schema follows the existing `schemas.ts` style: `pgTable("Play", …)`, camelCase column names (`guildId: text("guildId")`), text uuid ids via `randomUUID()`, `timestamp(..., { withTimezone: true })`.
- migration lives in `drizzle/postgres` as `0001_lain_stats.sql` (+ journal and snapshot), generated by drizzle-kit, applied by the existing `migrate()` at startup. no sqlite schema changes: stats are a no-op when the provider is not `PostgresProvider`.
- output is text only and lowercase (existing textify does that). never ping: every stats reply sends `allowedMentions: { parse: [] }`, people are shown by guild display name, falling back to `<@id>`.
- "played" = `playedMs >= 30_000` or `endReason = 'finished'`. hours played = sum of `playedMs` over all closed rows. skip rate = skipped / closed rows.
- ranges: `week` = last 7 days, `month` = last 30 days, `year` = last 365 days, none = all time (rolling windows, my call).
- busiest hour is computed in `Europe/Berlin` (ct 100 runs in utc, the server people are in cet).
- every recorder write is `void promise.catch(logger.error)`: never awaited by the player, never throws.
- typecheck and tests run in the ct 100 builder image (`docker build --target builder`), see task 5. no new dependencies.

## review focus

1. **bot restart mid-song:** the row stays open. on the next start it must be closed with `playedMs` = time until the next play in that guild, capped at `lengthMs`, `endReason = 'restart'`, not skipped. open vc sessions get `leftAt` = end of the last play in that guild, or `joinedAt`. test in task 2.
2. **skip vs finished:** lavalink v4 sends `replaced` when `skip` starts the next track and `stopped` for stop/skip on an empty queue. a track ending `replaced`/`stopped` within 3 s of its length is finished, not skipped. tests in task 2.
3. **streams and unknown length** (`isStream` or `duration` 0): `lengthMs` = 0, `playedMs` is wall time and never capped, never "finished early". test in task 2.
4. **pause:** paused time does not count as played. test in task 2.
5. **empty data:** a user with no plays, a range with no plays, a fresh server: replies say so in one line, no `NaN`, no `0/0`. tests in task 3 and 4.

### task 2: recorder

**files:**
- create: `src/lain/stats/recorder.ts`, `src/lain/stats/rules.ts`
- modify: `src/events/player/TrackStart.ts`, `TrackEnd.ts`, `PlayerCreate.ts`, `PlayerDestroy.ts`, `PlayerPaused.ts`, `PlayerResumed.ts`, `src/events/client/Ready.ts`
- test: `tests/stats.test.ts`

**interfaces:**
- consumes: `play`, `voiceSession` from task 1; `getDatabase()` from `src/database/factory.ts` (recorder uses `provider.db` only when `provider instanceof PostgresProvider`).
- produces (`rules.ts`, pure):
  - `playedMs(startedAt: number, endedAt: number, pausedMs: number, lengthMs: number, isStream: boolean): number` — wall time minus pauses, capped at `lengthMs` unless stream or `lengthMs` 0, never below 0.
  - `isSkipped(endReason: string, playedMs: number, lengthMs: number, isStream: boolean): boolean` — true for `replaced`/`stopped` unless `lengthMs > 0 && playedMs >= lengthMs - 3000`; false for everything else (`finished`, `loadFailed`, `cleanup`, `destroy`, `restart`).
- produces (`recorder.ts`), each returning `void` and swallowing errors into the logger:
  - `trackStarted(guildId: string, track: Track, at?: Date)` — closes any open row for the guild first (reason `replaced`), inserts a `play` row, keeps `{ id, startedAt, pausedAt, pausedMs, lengthMs, isStream }` in a per-guild map.
  - `trackEnded(guildId: string, reason: string, at?: Date)` — closes the open row via the rules; no-op if none.
  - `paused(guildId: string, at?: Date)` / `resumed(guildId: string, at?: Date)`
  - `joined(guildId: string, channelId: string, at?: Date)` — closes an open session for the guild first, inserts a `voiceSession` row.
  - `left(guildId: string, at?: Date)` — `trackEnded(guildId, "destroy")` then sets `leftAt`.
  - `closeStale(): Promise<void>` — the startup repair from review focus 1, one sql pass per table.
  - for tests: `recorderFor(db: PgLikeDB)` returns the same api bound to a given db; the default export binds lazily to `getDatabase()`.

- [ ] **step 1:** write `rules.ts` tests: `playedMs(0, 60_000, 10_000, 200_000, false) === 50_000`; capped `playedMs(0, 300_000, 0, 200_000, false) === 200_000`; stream `playedMs(0, 900_000, 0, 0, true) === 900_000`; `isSkipped("replaced", 40_000, 200_000, false) === true`; `isSkipped("replaced", 198_000, 200_000, false) === false`; `isSkipped("finished", 10_000, 200_000, false) === false`; `isSkipped("stopped", 600_000, 0, true) === true`.
- [ ] **step 2:** write recorder tests against pglite with explicit `at` dates: start → pause 10 s → resume → end `replaced` after 60 s gives `playedMs 50_000, skipped true`; start a then start b without an end closes a; `left()` closes the open track and the session; `closeStale()` on a guild with two open rows (a at t0, b at t0+90 s, lengths 200 s) gives a `playedMs 90_000` and b `playedMs 200_000`, both `restart`, and an open session gets `leftAt` = b's end.
- [ ] **step 3:** run them. expected: fail, modules missing.
- [ ] **step 4:** implement `rules.ts` and `recorder.ts`. hook calls: `TrackStart.run` → `trackStarted(player.guildId, track)`; `TrackEnd.run` → `trackEnded(player.guildId, payload.reason)` (type the payload as `TrackEndEvent`); `PlayerCreate` → `joined(player.guildId, player.voiceChannelId)`; `PlayerDestroy` → `left(player.guildId)`; `PlayerPaused`/`PlayerResumed` → `paused`/`resumed`; `Ready.run` → `void closeStale()` before `manager.init`. each hook is the first line of `run`, before any early return.

### task 3: queries

**files:**
- create: `src/lain/stats/queries.ts`
- test: `tests/stats.test.ts`

**interfaces:**
- consumes: tables from task 1; the recorder from task 2 to seed test data.
- produces:
  - `type Range = "week" | "month" | "year" | "all"`, `parseRange(word?: string): Range | null` (accepts `week|w|month|m|year|y|all`, `undefined` → `"all"`, anything else → `null`)
  - `overview(db, guildId, range): Promise<{ plays: number; playedMs: number; vcMs: number; joins: number; topSongs: Ranked[]; topPeople: Ranked[]; facts: Facts }>`
  - `personal(db, guildId, userId, range): Promise<{ plays: number; playedMs: number; skipRate: number | null; topSongs: Ranked[]; topArtists: Ranked[]; firstSong: { title: string; at: Date } | null }>`
  - `top(db, guildId, kind: "songs" | "artists" | "people", range, limit = 10): Promise<Ranked[]>`
  - `type Ranked = { key: string; label: string; uri?: string; count: number; playedMs: number }` (people: `key` = user id, `label` = id, the command resolves names)
  - `type Facts = { mostSkipped: Ranked | null; longestSessionMs: number | null; busiestHour: number | null; firstSong: { title: string; at: Date } | null }`
- counting uses only closed rows and the 30 s rule; songs group by `uri` falling back to lower(`title`), artists by lower(`author`). `vcMs` counts open sessions up to now.

- [ ] **step 1:** write tests on a seeded guild: overview counts a 10 s skip in `playedMs` but not in `plays`; `top("songs")` orders by count then playedMs; `range "week"` drops a row from 10 days ago; `busiestHour` for a play at `2026-11-27T20:30:00Z` is `21`; `personal` for an unknown user gives `plays 0`, `skipRate null`, empty lists; `parseRange("fortnight") === null`.
- [ ] **step 2:** run them. expected: fail.
- [ ] **step 3:** implement with drizzle `sql` aggregates, one query per number group; busiest hour via `extract(hour from "startedAt" at time zone 'Europe/Berlin')`.
- [ ] **step 4:** run all tests. expected: pass.
